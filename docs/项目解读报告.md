## 一句话定位

Windows 上的 Codex 实时状态，加上本机 Token Monitor 的多工具用量，经隐私过滤后以只读 HTTP JSON 交给 320×240 的 Cubic 副屏。屏幕只有两页：用量驾驶舱，以及按总用量前六名画出的水族箱。

## 整体架构与数据流

```
Codex CLI 生命周期 Hook（SessionStart / PreToolUse / PermissionRequest / Stop 等）
        │  POST http://127.0.0.1:8974/internal/event（仅回环，≤64KiB）
        ▼
Codex session JSONL（~/.codex/sessions/**/*.jsonl）── 约每 1.2s 增量 tail
        │
        ▼  normalizeBridgeEvent → SourceArbiter → BridgeSnapshot
Token Monitor 本地库（%APPDATA%\Token Monitor\hub-devices.json）── 每 5s 读一次
        │  全设备合计 TODAY/7D/ALL；额度环用本机账号；activeToolId 取当日增量最大的工具
        ▼
GET /api/v1/status + GET /api/v1/health（0.0.0.0:8973，IP 白名单，只读 GET）
        │  Cubic 每 1 秒 http.get
        ▼
Cubic Lua：第 1 页驾驶舱，第 2 页 Agent Tank；左右键手动切页，不自动轮播
```

`schemaVersion` 仍是 `1`。`--fixture <json>` 跳过 Hook / JSONL，直接喂样本快照；Token Monitor 读盘仍会按配置目录轮询。

## bridge

- `main.ts`：加载 `config.json`，装配 StateStore、StatusServer、SourceArbiter。live 模式启动 HookIngress 与 JsonlMonitor；无论 fixture 还是 live，都每 `tokenMonitorPollMs`（默认 5000）调用 Token Monitor 读盘。
- `server.ts`：只提供 `GET /api/v1/status` 与 `GET /api/v1/health`。非 GET 为 405，白名单外 403，其余 404。`status` 过期也返回 200。超过 `2147483647` 的 token 计数改成十进制字符串，避免 Cubic `sjson` 把大整数收成 32 位有符号数。`health` 在 Hook 已连接、JSONL 可用或 Codex 快照仍标记连接时返回 200，否则 503。Token Monitor 单独出现在 `sources.token_monitor`，它可用并不能把 503 抬成 200。
- `token-monitor.ts`：默认目录 `%APPDATA%\Token Monitor`。`hub-devices.json` 里全部设备的 allTime / today / 近 7 日历史相加，得到底部 `ALL` / `TODAY` / `7D`；额度窗口只取 settings 里的本机设备（否则第一台）。工具按全时段 token 取前 8。额度窗口若有未满的，就不用 100% 的空速率窗口冒充用量。`activeToolId` 是相邻两次采样里当日 token 增长最多的工具；连续 60 秒没有增长则清空。数据超过 12 分钟未更新标 `stale`。全机速率在今日总量 20 秒不变后视为 idle。
- `event-model.ts` / `normalizer.ts`：Hook 与 JSONL 收成同一事件。session 与子代理 ID 做加盐短哈希。活动摘要 `sanitizeLabel` 去掉路径、密钥形态和非 ASCII，截断 80 字符。任务标题 `sanitizeTitle` 去掉路径和密钥，保留中文，只留首行并截到 22 个字符；设备画屏时再剥非 ASCII。
- `jsonl-monitor.ts`：只 tail 最新修改时间的一个 `.jsonl`。识别官方用量对象的 `primary` / `secondary`，以及 `used_percent` / `window_minutes` / `resets_at`。用户消息经 `sanitizeTitle` 后写入会话标题，不转发正文。
- `source-arbiter.ts`：同一 session 最近 10 秒内 Hook 优先，不挡住其他 session 的 JSONL。终态不被更旧的 working 倒退。`token_count` 只更新用量和上下文，不改状态。无标题时用 `Codex Task`。
- `hook-ingress.ts` / `hook-cli.ts`：Hook 口拒绝非回环绑定。hook-cli 失败时会尝试拉起 Bridge，并向 Codex 打印 `{}`，避免拦住 `PermissionRequest`。
- `codex-protocol.ts`：`connectCodex()` 会抛错。直连 app-server 已放弃，这里只留协议字段边界。
- `state-store.ts`：内存快照、两路 Codex 源健康度，以及 Token Monitor 快照。
- `scripts/manage-installation.mjs` 与启动文件夹脚本：幂等写入本应用的 Hook 与登录快捷方式，卸载只删自己的条目。

公开 `status` 仍包含 `codex_connected`、`status`、`primary_task`、`activities`（最多 5 条）、`usage.windows`（300 / 10080 分钟）、`other_active_task_count`，以及 `token_monitor`（`activeToolId`、最多 8 个 `tools`、`rate`、`today` / `last7` / `allTime`）。

## cubic 包

- 包版本 `0.6.0`，应用 id `codex_monitor`，固件目标 v1.212。安装走 tar + `manifest.json`；开发期用 `cubic/scripts/deploy-dev.mjs` 直传 Lua、网页和资源，并保留设备上的 `config.json`。
- 每秒请求 `/api/v1/status`，超时 2000ms。连续 3 次失败进入 offline，保留最后数据并降暗。天气每 60 秒走固件 `http.cubicserver` 的 `/v1/weather/now?lang=en`，地点来自 `/sd/apps/settings.json`。
- 不自动轮播。LEFT / RIGHT 切页，HOME 退出。`CODEX_MONITOR_APP.stop()` 释放定时器、按键和 LVGL 对象。屏幕只画 ASCII；剥空后的占位是 `[zh]`，天气城市和概况再把 `[zh]` 显示成 `--`。
- **第 1 页**：状态圆点、本日 token 最高工具的短名（没有 `todayTokens` 时用排名第一，没有数据时显示 `CODEX`）、大字状态、本地时钟、天气、一行任务摘要、8 个用量环、底部 `RATE / TODAY / 7D / ALL`。环内图标 17px、圆形裁切；有素材的工具用 `assets/tm_<id>.png`，否则用短名首字母。DeepSeek 的 hub id 是 `dsh`。余额颜色：`>=80` 绿，`>=50` 蓝，`>=20` 琥珀，其余红。任务行是英文状态加上最近一条活动摘要，不是 `primary_task.title`。
- **第 2 页 Agent Tank**：总用量前 6 名各一条鱼，体型按名次固定（56×28 到 26×12）。颜色档与圆环相同；没有额度或离线时为灰。主角鱼优先是 `codex`，否则是第一名。working 时全员沿固定泳道游动，速度随全机 token 速率升高（约 7–38 px/s），到缸边调头。idle / offline / 断连时沉底并显示 `z`。`needs_user` 时主角贴右侧玻璃、标 `!`，并显示 `NEED INPUT`。`error` 时主角用翻白肚贴图。吐泡优先给等待输入的主角，否则给 `activeToolId` 对应的上榜鱼。尾巴后跟 17px 圆形 logo。底栏与第 1 页相同。鱼和 logo 用 LVGL 线性动画沿泳道移动，到边才换向；百分比标签按 4px 一档跟随。没有动画接口时，按真实经过的时间在 32ms 定时器里降级挪动，单拍最多补 48ms。只在第 2 页可见时推进。缸底有水草和小虾贴图。
- 快照里的 `primary_task`（含标题、模型、上下文）、`other_active_task_count`、Codex 5 小时 / 7 天窗口会被解析进内存，当前两页都不绘制。`render_details()` 是空函数。`STAGE_ICON` 没有被引用。活动不再单独成页。
- 管理页 `main.html` 保存 host、port 和可选 label。label 写入设备 `config.json`，`main.lua` 不读它。

## 风险

1. `bridge/config.json` 被 Git 跟踪，里面有内网白名单。这和 `deployment.md`「不要提交本机 IP」不一致。`10.23.2.0` 是本机以太网在 `/16` 下的主机地址，不是网段号。
2. 每个 Hook 事件都会拉起一次 `node --import tsx`。Bridge 不在时 hook-cli 会静默拉起它；失败只等约 180ms 再试一次，`PermissionRequest` 事件可能丢掉。这是为了不拦住 Codex 批准。
3. 默认隐私盐是 `codex-monitor`，短哈希 12 位，常见 session id 形态存在被字典反推的空间。
4. 管理页跨域请求 health 时，Origin 必须落在 IP 白名单里。设备换 IP 后，测试连接会表现为网络失败。
5. JSONL 只跟踪最新的一个 session 文件。并行的旧会话要靠 Hook 更新，否则会停在上次状态。
6. 总量字段在设备端用 `parse_count`：能读数字字符串，也能把 32 位溢出负数加 `2^32` 还原。单个工具的 `todayTokens` 走 `valid_number`，负数会被丢掉。若固件把超大 `todayTokens` 解成负数，顶部「本日最高工具」会退回排名第一。
7. Lua 对 `tmr` / `lv` / `key` 做了两套 API 探测，实机依赖固件 1.212。固件升级是主要脆弱面。


## 2026-11-20 故障修复记录

### 故障现象

副屏显示离线、连不上。排查时 Bridge 进程与 8973 端口正常，设备 `10.23.2.209` 的 TCP 连接持续建立（大量 TIME_WAIT），网络层与白名单均无问题。

### 根因

`/api/v1/status` 响应膨胀到 **303 KB**，其中 `usage.windows` 累积了 **4194 条**（正常应为 2 条：300 分钟 + 10080 分钟窗口）。设备端 Lua 每秒轮询、2000ms 超时，无法下载解析此体积的 JSON，连续 3 次失败后判定 offline。

膨胀链条：`source-arbiter.ts` 的 `sessions` Map 只进不出（Bridge 自 11-17 启动以来见过的所有会话永久驻留），`project()` 对全部会话 `flatMap(session.usage)`；`normalizer.ts` 的 `normalizeUsageWindows` 不做去重，直接透传。

### 修复（三处）

1. `bridge/src/normalizer.ts`：`normalizeUsageWindows` 改为按 `windowDurationMins` 去重，同一窗口只保留最后出现的一份。输出恒为 2 条，与累积会话数无关。
2. `bridge/src/source-arbiter.ts`：新增 `SESSION_TTL_MS = 12h`，`project()` 时驱逐超过 12 小时无活动且处于终态的会话，防止内存与任务列表无界增长。
3. `bridge/scripts/start-bridge-hidden.vbs`：增加启动留痕，每次拉起向 `bridge/logs/startup-launcher.log` 追加时间戳与结果（只写 ASCII，TextStream 默认编码写不了中文路径）。

### 验证

- `npm test` 60/60 通过，`tsc --noEmit` 无错误。
- 修复后重启 Bridge，响应 2091 字节 / 2 个窗口，health 全绿，设备自行恢复。
- 开机启动链路（启动文件夹 `.lnk` → wscript → vbs → `start-bridge.ps1`）逐级实测通过。

### 同日清理

- 删除无触发器的死计划任务 `CodexMonitorBridgeAdHoc`。
- 删除桌面手动启动入口 `启动副屏桥接.lnk`（与开机自启 + hook-cli 兜底重复；`start-bridge.ps1` 本体保留在 `bridge/scripts/`）。

### 历史日志误报说明

旧 `bridge.err.log` 中的 `'\"C:\Program Files\nodejs\node.exe\"' 不是内部或外部命令` 并非开机自启故障，而是某次从类 Unix shell 手动执行时引号被反斜杠转义的一次性报错（已复现确认）。PS 5.1 的 `Start-Process` 空格路径写法经原样复刻测试无问题。

### 遗留事项

- `scripts/install-startup.ps1` 为无 BOM 的 UTF-8 且含中文注释，PS 5.1 按 GBK 误读注释（不影响执行），改动该文件时需带 BOM 保存。同理，任何含中文字面量的 `.ps1` 必须带 BOM，否则字符串可能被 GBK 误解码截断。
- VBScript `TextStream` 默认 ASCII/GBK 编码，不能写含中文路径的日志；vbs 留痕保持纯 ASCII。
