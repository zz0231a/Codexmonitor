# Codex Cubic Monitor 设计说明

## 1. 目标

为 320×240 Cubic 设备开发一个 Codex 状态副屏应用，实时展示本机 Windows 上 Codex Desktop 的工作状态、当前主任务、近期活动、5 小时与 7 天剩余用量，以及 Cubic 系统天气。

整体视觉采用已确认的深色像素终端风，强调远距离快速读取。应用只展示经过筛选的摘要，不显示完整提示词、回复正文或工具参数，也不提供控制 Codex 的能力。

## 2. 交付范围

项目包含两个独立组件：

1. Windows 桥接程序：随 Windows 登录启动，连接本机 Codex `app-server`，把结构化事件归一化后，通过局域网只读 HTTP 接口提供给设备。
2. Cubic 应用：Lua + LVGL 应用包，轮询桥接接口，结合 Cubic 系统天气渲染两页界面。

不在本期范围内：远程控制 Codex、展示完整对话、修改 Codex 配置或任务、消费用量重置额度、向公网暴露桥接接口、官方社区上架。

## 3. 总体架构

```text
Codex Desktop / shared app-server
        │ 本机结构化协议
        ▼
Windows Bridge
        │ 状态归一化与隐私过滤
        │ 只读 HTTP JSON（局域网）
        ▼
Cubic Lua App
        ├─ 第 1 页：Codex + 天气 + 用量
        └─ 第 2 页：任务活动详情
```

桥接程序是协议隔离层。Codex 升级造成 `app-server` 字段变化时，优先只调整桥接程序，不改变设备端数据结构和界面逻辑。

## 4. Windows 桥接程序

### 4.1 数据来源

桥接程序连接本机共享 `app-server`，读取：

- 任务列表、任务标题、最近活跃时间与运行状态；
- 当前 turn 状态；
- 经过归类的近期活动事件；
- 模型名称、上下文或 token 使用信息（仅在接口实际提供时）；
- `account/rateLimits/read` 返回的用量窗口；
- `account/rateLimits/updated` 推送的滚动更新。

5 小时和 7 天窗口以接口返回的 `windowDurationMins` 识别，不依赖 `primary`、`secondary` 的固定顺序。剩余比例按 `100 - usedPercent` 计算并限制在 0–100。重置时间使用 `resetsAt` 转为本地时间或剩余时长。

### 4.2 主任务选择

同时存在多个任务时，桥接程序只选择一个主任务展示，优先级固定为：

1. 等待用户处理或确认的任务；
2. 正在运行的任务；
3. 最近活跃的任务。

同一优先级内按最近活跃时间排序。第一页额外显示其他活动任务数量，但不自动轮播不同任务，避免屏幕内容频繁跳变。

### 4.3 状态归一化

设备端只接收以下稳定状态：

| 状态 | 含义 |
| --- | --- |
| `offline` | 桥接程序未连接 Codex 或设备无法连接桥接程序 |
| `idle` | Codex 可用，但没有正在执行或等待处理的任务 |
| `working` | 主任务正在分析、调用工具或生成回复 |
| `needs_user` | 主任务等待用户确认、授权或输入 |
| `done` | 最近主任务已经正常完成 |
| `error` | 主任务失败或协议读取出现不可恢复错误 |

活动阶段归类为：分析、读取、执行工具、等待用户、生成回复、完成和失败。无法识别的事件显示为“处理中”，不把原始参数直接发送给设备。

### 4.4 只读 HTTP 接口

桥接程序提供版本化接口：

```text
GET /api/v1/status
GET /api/v1/health
```

`/api/v1/status` 返回设备渲染需要的单一快照，包括服务器时间、连接状态、主任务、近期活动、用量窗口和其他活动任务数量。`/api/v1/health` 只用于安装与故障检查。

接口不提供 POST、PUT、PATCH 或 DELETE 操作。桥接程序默认绑定局域网地址，端口可配置；响应体不包含完整提示词、回复正文、命令参数、文件正文、账户标识或认证凭证。

### 4.5 启动与配置

桥接程序提供一次性安装脚本，建立当前用户级 Windows 登录启动项，不要求管理员权限。配置至少包括监听地址、端口和允许的设备地址；日志默认只记录连接、状态转换和错误，不记录会话正文。

## 5. Cubic 应用

### 5.1 应用结构

```text
codex_monitor/
└── package/
    ├── app.info
    ├── main.lua
    ├── main.png
    ├── info.html
    ├── main.html
    ├── assets/
    └── font/
```

`main.html` 用于配置 Windows 桥接程序 IP 和端口，并提供连接测试。应用配置保存在自身目录，不修改 Cubic 的系统天气设置。

### 5.2 页面一：Codex、天气与用量

页面布局分为三块：

- 左上：Codex 当前状态、主任务标题、当前阶段、运行时长、上下文占用、工具调用次数及最近更新时间；
- 右上：跟随 Cubic 系统设置的城市、当前天气、体感温度、湿度、风力、降雨概率和短时趋势；
- 底部：5 小时和 7 天剩余用量进度条，以及各自的重置时间。

若上下文占用或某个用量窗口不可用，相应位置显示 `--`，不保留过期值。用量低于 20% 时使用警示色，归零时使用错误色。

### 5.3 页面二：任务活动详情

页面显示：

- 最近五条活动摘要与时间；
- 当前主任务状态；
- 模型名称；
- 上下文占用；
- 当前是否需要用户处理；
- 其他活动任务数量。

所有活动只展示动作类别和安全摘要，例如“读取项目文件”或“执行测试”，不显示路径、命令参数、提示词或回复正文。

### 5.4 交互与轮播

- 两页每 30 秒自动切换；
- `LEFT`、`RIGHT` 立即手动切换页面；
- 手动切换后重新开始当前页的 30 秒计时；
- `HOME` 短按退出应用；
- 页面底部显示当前页圆点和自动切换倒计时提示。

设备每 1 秒请求一次桥接状态。天气使用 Cubic 系统已有设置和数据源，刷新频率遵循系统能力，不由本应用高频请求外部天气 API。

## 6. 离线与错误处理

- 设备连续请求失败后进入 `offline`，保留最后一次非敏感数据但整体降暗，并显示数据最后更新时间；
- 恢复连接后自动返回实时状态，不要求重启应用；
- 桥接程序与 Codex 断开时继续响应 HTTP，但明确返回 `codex_connected = false`；
- 字段缺失按单字段降级，不因上下文、天气或用量缺失导致整页失败；
- Lua 定时器、按键回调、字体和图片资源在退出或重新加载时全部释放。

## 7. 安全与隐私

- 桥接程序只读取 Codex 状态，不发送控制请求；
- 不向设备发送完整提示词、回答、命令参数、文件内容、账户 ID、API Key 或认证令牌；
- HTTP 接口限制在可信局域网，支持配置允许访问的设备地址；
- 日志不记录会话正文；
- 用量接口仅读取，不调用任何额度消费或重置操作；
- 社区发布前删除开发机地址、账户数据和测试日志。

## 8. 验证方案

### 8.1 桥接程序

- 使用固定协议样本测试状态归一化、多任务排序、用量窗口识别和隐私过滤；
- 验证 `usedPercent` 到剩余比例的边界值：0、20、100 和缺失值；
- 验证 Codex 空闲、工作、等待确认、完成、失败和断连状态；
- 验证 HTTP 接口只有只读路由，并且响应中不存在受限字段；
- 验证 Windows 登录启动和无管理员权限安装。

### 8.2 Cubic 应用

- 在 320×240 实机验证两页文字不截断、颜色可辨识和 30 秒自动轮播；
- 验证 `LEFT`、`RIGHT`、`HOME` 行为；
- 验证桥接离线、Codex 断开、天气缺失及单个用量窗口缺失；
- 长时间运行并反复退出、重载，确认定时器、回调和字体资源释放；
- 验证设备与电脑不在同一网段时给出明确配置提示。

## 9. 完成标准

满足以下条件视为本项目完成：

1. Windows 桥接程序能够随登录启动并稳定读取本机 Codex 状态；
2. Cubic 应用能在实机显示两页界面并每 30 秒自动轮播；
3. 5 小时与 7 天剩余用量来自真实接口，并正确显示重置时间；
4. 天气跟随 Cubic 系统设置；
5. 多任务选择符合既定优先级；
6. 断线和字段缺失时可降级运行；
7. 设备接口和日志不泄露完整会话内容或认证信息；
8. 完成 Lua 资源释放、桥接单元测试和 320×240 实机验证。
